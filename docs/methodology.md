# Методика и модель угроз

## Что атакующий может менять

Атакующий может заменить метки у выбранной доли обучающих строк до обучения модели.
Он не меняет признаки, тестовую выборку, код обучения, параметры модели или генератор данных.
Выбор строк случайный: атакующий не подбирает оптимальные для максимального вреда примеры.
Это сценарий нарушения целостности обучающих данных, а не атака на уже обученный файл модели.

## Порядок эксперимента

1. Генерируются 2000 синтетических примеров: 12 признаков, 6 информативных, 2 избыточных,
   2 кластера на класс, `class_sep=1.3`, `flip_y=0`. Остальные параметры генератора
   имеют значения по умолчанию из зафиксированной версии scikit-learn.
2. Индексы делятся 70/30 со стратификацией по истинным меткам. Пересечений нет.
3. Для каждой доли подмены создается новая копия обучающих меток.
4. В случайном порядке выбираются первые `floor(n_train * fraction)` индексов.
   На них метка становится `1 - y`. Для всех бюджетов одного повтора порядок одинаков.
5. Для каждого бюджета заново обучается `Pipeline(StandardScaler, LogisticRegression)`.
   Масштабирование обучается только на train, модель обучается на соответствующих метках.
6. Предсказания сравниваются с неизменными истинными метками test.
7. Процедура повторяется 5 раз. Повтор `i` использует `seed + 3*i` для данных,
   следующий seed для разделения и еще следующий для подмены.

Для чистого baseline используется точка с бюджетом 0. Никакие параметры не подбираются по тесту.
Test в этой версии служит для измерения заранее заданного эксперимента.
Для подбора защиты или параметров понадобится отдельная validation-выборка.

## Метрики и парность

- Accuracy: доля правильных ответов на чистом тесте.
- Balanced accuracy: средняя полнота по двум классам.
- F1: гармоническое среднее precision и recall для класса 1; при нулевом знаменателе 0.
- Матрица ошибок: по строкам истинные классы, по столбцам предсказанные, порядок `[0, 1]`.

В сводке указаны среднее и выборочное стандартное отклонение (`ddof=1`). Это описательный
разброс между повторами, не доверительный интервал. Повторы меняют сразу данные,
разделение и выбор подмен; эти источники вариации отдельно не оцениваются.
Разность считается относительно baseline **того же повтора**. Для accuracy
CLI и HTML показывают ее в процентных пунктах. Отрицательное значение означает ухудшение.

## Проверяемые свойства

Тесты проверяют число и индексы подмен, неизменность исходных массивов,
вложенность бюджетов, повторяемость, непересечение train/test и обучение scaler только на train.
Полная инверсия служит контрольной крайностью: у симметричной бинарной модели ответы
должны смениться на противоположные. Монотонное ухудшение при каждом бюджете не является условием прохождения тестов.

JSON сохраняет параметры, версии, seed, хеши исходных выборок и измененных индексов,
индивидуальные измерения и сводку. Хеши нужны для проверки воспроизводимости. Сами по себе они
не защищают данные от атакующего. Для повторения нужны те же данные генератора,
параметры и окружение. Между платформами и версиями возможны численные различия.

## Ограничения

Один генератор, одна модель, одна случайная атака. Синтетические классы не обозначают
реальный трафик, вредоносные файлы или пользователей. Результат не оценивает безопасность
боевой системы. Проверка допустимости меток 0/1 не обнаруживает их подмену на другие
допустимые метки. В CPU-режиме защиты и целевые атаки не реализованы. Отдельный опыт с Qwen
описан в [методике Qwen](qwen-methodology.md).
