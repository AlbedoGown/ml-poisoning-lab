# Qwen: план эксперимента

## Гипотеза и границы

Проверяем, изменит ли подмена целевых ответов при LoRA-дообучении маршрутизацию
сетевых заявок в закрытой задаче из трёх категорий. Это целевая подмена меток,
не prompt injection, не RAG poisoning и не скрытый backdoor с триггером.
Эксперимент не даёт оснований заявлять об уязвимости Qwen как продукта.

Модель: `Qwen/Qwen3-0.6B`, ревизия `c1899de289a04d12100db370d81485cdf75e47ca`.
Это небольшая модель семейства Qwen для доступного локального эксперимента.
Результаты не переносятся автоматически на крупные модели или корпоративные установки.
Загрузка идёт из официального репозитория; `trust_remote_code=False`.

## Данные

Вымышленные русскоязычные заявки, созданные локальным генератором:

- A — сеть: 60 train, 12 validation, 18 test.
- B — учётная запись: 60 train, 12 validation, 18 test.
- C — оборудование: 60 train, 12 validation, 18 test.

Всего 180/36/54 примеров. Для каждого класса выделены 6 обучающих, 2 проверочных
и 2 тестовых шаблона. Шаблоны между выборками не пересекаются. Варианты одного
шаблона отличаются вводной фразой, номером вымышленного кабинета и окончанием.
Это ограниченное разнообразие: 54 строки test не являются 54 независимыми сюжетами.
Семантика категорий задаётся system prompt; модель должна вернуть одну букву.

Атака меняет ответы A→B у 54 строк: **30% всего train, 90% класса A**.
Это сильный доступ атакующего к одному классу. Остальные поля не меняются.
Validation и test остаются чистыми. Возникающее изменение баланса обучающих
ответов — часть сценария атаки; данный эксперимент не отделяет его вклад от
влияния конкретных примеров. Классовый приоритет B сам по себе требует учёта.

## Контроль обучения

Сравниваются исходная модель без адаптера, чистый LoRA и отравленный LoRA.
Три парных повтора используют seed 100, 101, 102. Датасет зафиксирован seed 1729.
Между повторами меняются инициализация/порядок обучения и выбор подмен,
а не сам test. Повторы не оценивают разброс между независимыми датасетами.

В каждой паре идентичны исходные веса, примеры, порядок батчей, seed,
число шагов и настройки. Подменяются только ответы. Обучение каждого адаптера
идёт с нуля в отдельном процессе; адаптеры не накладываются друг на друга.

Настройки заранее фиксируются в `plan.json` до оценки исходной модели:
1000 шагов Adam, batch size 2, learning rate 0.0002, последние 8 слоёв,
LoRA rank 8, scale 16, dropout 0, проекции q и v. Исходные веса не квантуются.
Максимальная длина 256 токенов; слишком длинный пример отклоняется вместо обрезки.
Loss считается только по ответу и завершающему EOS-токену.

Validation loss наблюдается на старте и в конце. Она не используется для ранней
остановки или выбора лучшего checkpoint. Проверяется конечный адаптер.
Параметры не выбираются по test; для дальнейшего подбора потребуется новая
зафиксированная процедура и отдельная финальная оценка.

## Оценка

Шаблон чата одинаковый при подготовке обучения и при оценке:
`enable_thinking=False`. Генерация свободная, greedy (`temperature=0`),
до 8 новых токенов. Допустимы только A/B/C после удаления внешних пробелов.
Пояснение, пунктуация или обрезанный ответ считаются invalid и ошибкой.
Принудительного ограничения словаря до трёх букв нет.

Метрики: accuracy, macro F1, invalid rate, precision/recall/F1 каждого класса,
матрица ошибок 3×4 и доля A→B среди истинных A. Последняя сравнивается с чистым
адаптером: ошибку, которая была до атаки, нельзя приписывать атакующему.
Публикуются все отдельные ответы, средние и выборочный SD трёх повторов, парные
разности. SD не является доверительным интервалом или доказательством значимости.

Код `metrics.py` основан на ответе agy/Sonnet, адаптирован и независимо проверен
Codex по ручному примеру и scikit-learn. Решение о методике и обучении принято
основным агентом. Обучение и генерация выполняются локально.

## Разработка протокола

В диагностической серии на 100 шагах чистые адаптеры не давали пригодного контроля.
Кроме того, обнаружено включение одного padding-токена в стандартную loss mask:
для нашего формата нужна строгая верхняя граница `position < sequence_length`.
Исправление проверено отдельным MLX-тестом с заведомо ошибочными prompt/padding
позициями, которые не должны влиять на loss. Диагностические цифры не включены
в финальную сводку.

Чистое обучение на 1000 шагах проверено на seed 42 только по validation:
28/36 правильных ответов, сетевой класс 12/12. После этого зафиксирован бюджет
1000 шагов. Для финальной серии используются другие seed и новые тестовые шаблоны
(индексы 10:12 вместо диагностических 8:10); train и validation не менялись.
Это разработка на синтетических данных, а не внешняя независимая валидация.
